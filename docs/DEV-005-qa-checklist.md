> **Version:** 0.9 · **Updated:** 2026-09-18 · **Owner:** 운영 및 백오피스 PM\
> **Status:** 검토 대기 — 본문 작성 완료, 확정 전\

> **문서 역할:** `COM-004 §6`이 정한 테스트 기준을 **실제로 눌러 볼 목록**으로
> 푼다. 기준은 거기 있고, 여기에는 무엇을 눌러야 하는지가 있다.\
> **선행 문서:** `COM-004 §6`(테스트 기준), `COM-003 §4`(Screen ID),
> `DEV-002`(Route)

## 0. 이 문서를 쓰는 법

### 0-1. 언제 돌리나

```text
PR 마다      바꾼 화면의 줄만. §2 를 함께 본다
배포 전      §1 전부 + 바꾼 Area 전부
주에 한 번   §1 전부
```

`COM-004 §6-3` 이 "바꾼 화면을 실제로 연다. **버튼을 누른다**" 고 정한다.
화면이 뜨는 것과 동작하는 것은 다르다 — `'use server'` 파일에서 상수를
내보낸 실수는 빌드를 통과하고 버튼을 누를 때만 터졌다(2026-09-10).

### 0-2. 무엇을 확인하고 무엇을 확인하지 않나

`COM-004 §6-2` 가 정한 대로 **AI 출력은 내용을 단언하지 않는다.**

```text
확인한다      JSON 으로 읽히는가 · 필수 칸이 있는가 · 보기가 4개인가
              정답이 학생 문구에 섞여 있지 않은가
확인 못 한다  말투가 좋은가 · 문제가 적절한가
```

말투와 적절성은 사람이 눈으로 보고, 이상하면 `prompt-lab` 에서 프롬프트를
고친다. 체크리스트의 Fail 로 적지 않는다 — 통과 기준을 세울 수 없는 항목이다.

### 0-3. 결과를 어디에 적나

지금은 **이 파일의 체크박스에 적는다.** 혼자 돌리는 동안은 그게 가장 짧다.

회차를 쌓아야 할 때가 오면 CSV 로 옮긴다. `xlsx` 를 만들려고 라이브러리를
들이지 않는다(CLAUDE.md · 스택을 임의로 늘리지 않는다). 만드는 법은
`prompt-lab/_history.ts` 에 선례가 있다 — **BOM 을 안 붙이면 Excel 이 한글을
깨뜨린다**는 것까지 거기 적혀 있다.

### 0-4. 체크리스트를 고치는 때

**화면을 고친 PR 에서 같이 고친다.** 나중에 몰아서 하면 화면은 바뀌었는데
목록은 그대로인 상태가 조용히 생긴다. 이 문서가 저장소 안에 있는 이유가
그것이다.

## 1. 먼저 보는 것 — 깨지면 안 되는 선

**여기부터 본다.** 아래는 기능이 아니라 이 제품이 지키기로 한 약속이다.
하나라도 Fail 이면 배포하지 않는다.

### 1-1. 학생에게 보이면 안 되는 것

- [ ] 학생 화면(`/home` · `/home/today` · `/mission`)에 **상세 평가점수**가 없다 (COM-003)
- [ ] 학생 화면에 **Logic Gap** 이 없다 (COM-003)
- [ ] **Answer Lock 데이터가 어느 시점에도** 학생에게 안 보인다 (CLAUDE.md)
- [ ] `verified_answer` 가 **문제 진행 중에는** 안 보인다 (COM-002 §17)
- [ ] `verified_answer` 가 **문제를 종료할 때는** 정답·해설로 보인다 (COM-001 §8)

마지막 둘은 짝이다. 하나만 보면 반대쪽이 깨진 것을 놓친다.

### 1-2. 학생에게 말하는 방식

- [ ] `needs_review` 가 **"실패" 로 보이지 않는다** — 「한 번 더 도전」 (COM-003 §7)
- [ ] 힌트 사용이 **감점처럼 보이지 않는다** (CLAUDE.md)
- [ ] 오류가 **학생 잘못처럼 보이지 않는다** — "잠깐 멈췄어. 다시 말해줄래?"
- [ ] 학생 어휘 ↔ 부모 어휘가 어긋나지 않는다. 변환은 `copy.ts` 한 곳 (COM-003 §7)

### 1-3. 학습 로직 (COM-001 §19)

- [ ] `system_interrupted` · `verification_failed` 가 **정답률과 완료 문제 수에 안 들어간다**
- [ ] Persona 를 `friend` ↔ `villain` 으로 바꿔도 **정답 · 평가 · 난이도 · 검증이 같다**
- [ ] 세션을 마쳐도 **Student Memory 가 초기화되지 않는다**
- [ ] 새 학습을 시작해도 **과거 학습기록이 지워지지 않는다**

### 1-4. 계정 경계 (COM-003 §4.2 · 2026-09-17 개정)

- [ ] **부모 계정**으로 `/home` · `/mission` · `/students` · `/onboarding/persona` 를 열면 `/parent` 로 간다
- [ ] **아이 계정**으로 `/parent` · `/parent/reports` · `/parent/my` 를 열면 `/home` 으로 간다
- [ ] `/onboarding/student` 는 **부모만** 열린다 (아이는 `/home` 으로)
- [ ] 부모 화면 어디에도 학생 영역으로 가는 링크가 없다
- [ ] 학생 화면 어디에도 부모 영역으로 가는 링크가 없다

주소를 직접 쳐서 확인한다. **링크가 없는 것과 못 들어가는 것은 다르다.**

### 1-5. 운영자 (COM-007 §7)

- [ ] `admin_user` 에 없는 계정으로 `/admin` 을 열면 **404** 다 (「권한 없음」이 아니다)
- [ ] `is_active = false` 인 운영자도 **404** 다
- [ ] 마스킹 해제는 **사유 없이 안 된다**
- [ ] 마스킹 해제가 `audit_log` 에 남는다
- [ ] 어드민 화면 어디에도 **대화 원문**이 없다
- [ ] 운영자 추가·권한 변경이 **화면에서 안 된다** (SQL 로만)

## 2. 회귀 — 2026-09-17 변경분

**아직 손으로 확인되지 않았다.** 하루에 계정 구조가 바뀌었으므로 다음 배포
전에 이 절을 통째로 돌린다.

### 2-1. 로그인 착지 (COM-003 §4.1 개정)

- [ ] 부모로 로그인 → `/parent` 로 간다 (전에는 `/students`)
- [ ] 아이로 로그인 → `/home` 으로 간다
- [ ] 이미 로그인한 채 `/login` 을 열면 부모는 `/parent`, 아이는 `/home` 으로 간다
- [ ] 이미 로그인한 채 `/signup` 을 열어도 같다
- [ ] 가입 직후(메일 확인이 꺼진 환경)에는 `/onboarding/student` 로 간다

### 2-2. 학생 등록 (DEV-002 §3 · COM-002 §4-1 개정)

- [ ] `/parent/my/students/new` 가 **보호자 화면 안에서** 열린다. 하단 Nav 가 그대로 있다
- [ ] 아이 아이디·비밀번호 칸이 **펼쳐진 채 필수**다
- [ ] 아이디를 비우고 등록하면 서버가 막는다 (화면 검사만 믿지 않는다 — 개발자 도구로 `required` 를 지우고 눌러 본다)
- [ ] **중복확인** 버튼: 이미 쓰는 아이디 → 빨간 글씨 · 등록 버튼이 막힌다
- [ ] 중복확인 뒤 아이디를 고치면 **결과가 사라진다** (「쓸 수 있어요」가 남지 않는다)
- [ ] 중복확인 버튼이 폼을 제출하지 않는다 (`type="button"`)
- [ ] 등록을 마치면 `/parent/my/students/[id]` 로 간다
- [ ] 둘째를 등록해도 **첫째의 「지금 공부하는 아이」 쿠키가 안 바뀐다**
- [ ] 등록 화면에 **파트너 고르기가 없다**
- [ ] `/onboarding/student` 에서 등록을 마치면 `/parent` 로 간다

### 2-3. Persona (COM-001 §3 개정)

- [ ] 등록한 학생의 기본 파트너가 `friend`(메티)다
- [ ] 아이가 학생 HOME 의 **「파트너 바꾸기」**로 `/onboarding/persona` 에 간다
- [ ] 고르면 `/home` 으로 돌아오고 값이 바뀌어 있다

### 2-4. 이벤트와 어드민 (COM-002 §14 개정)

- [ ] 아이가 처음 로그인하면 `child_login_first` 가 **한 번만** 남는다 (두 번째 로그인에 또 안 남는다)
- [ ] `/admin` 퍼널의 「아이 첫 로그인」 칸에 `2026-09-17부터` 가 적혀 있다
- [ ] 아이디 없는 학생이 있으면 `/admin` 에 노란 줄이 뜬다
- [ ] `/admin/students/[id]` 에 「이용 깊이」가 나온다 (평균 턴 · 힌트 분포 · Drill-down 단계)
- [ ] 대화가 없는 학생은 「대화 기록 없음」이다 (0 으로 나눈 `NaN` 이 아니다)

## 3. 화면별

**만들어진 화면만 적는다.** 없는 화면은 §5 에 있다.

### 3-1. AUTH · 회원/인증

#### `AUTH-001` 로그인 · `/login`
- [ ] `@` 가 있으면 부모 이메일, 없으면 아이 아이디로 본다
- [ ] 「보호자용」/「학생용」을 **고르게 하지 않는다**
- [ ] 틀렸을 때 **어느 쪽이 틀렸는지 알려주지 않는다** — 없는 계정 · 미확인 · 틀린 비밀번호가 같은 문장이다

마지막 줄이 중요하다. "그런 이메일 없음" 은 가입 여부를 확인해 주는 답이라
남의 이메일로 회원인지 알아낼 수 있다. 아이 아이디도 마찬가지다.

#### `AUTH-002` 회원가입 · `/signup`
- [ ] 이름 · 전화번호 · 생년월일이 없으면 가입이 안 된다 (트리거가 되돌린다)
- [ ] 비밀번호 8자 미만이면 막힌다
- [ ] 이미 가입된 이메일도 **같은 화면**을 보여준다 (가입 여부를 알려주지 않는다)
- [ ] 이 화면만 학생 어휘를 쓰지 않는다 — 「보호자 이름」 · 「회원가입」

### 3-2. STU · 학생

#### `STU-001` 첫 학생 등록 · `/onboarding/student`
§2-2 와 같다.

#### `STU-002` 학생 선택 · `/students`
- [ ] 아이 계정으로 열린다. 부모는 `/parent` 로 간다
- [ ] 「학생 한 명 더 등록하기」가 **없다** (추가는 `MY-004`)
- [ ] 「보호자 화면」 링크가 **없다**

#### `STU-003` Persona 선택 · `/onboarding/persona`
- [ ] 아이만 열린다
- [ ] 「말투만 달라요」가 적혀 있다 — 난이도가 바뀐다고 쓰지 않는다 (COM-001 §19)

#### `STU-004` 학생 HOME · `/home`
- [ ] 상태에 맞는 버튼이 뜬다 (최초 / 오늘 시작 전 / 진행 중 / 완료)
- [ ] 「파트너 바꾸기」가 있다
- [ ] 「나가기」로 로그아웃된다 — 아이는 부모의 계정 관리에 못 들어가므로 여기가 없으면 나갈 길이 없다
- [ ] 없는 값(포인트 · 연속 학습 · 도감)을 **지어내 보여주지 않는다**

#### `STU-005` 오늘의 기록 · `/home/today`
- [ ] 상세 평가점수와 Logic Gap 이 없다
- [ ] `needs_review` 가 「한 번 더 도전」으로 나온다
- [ ] 하루를 안 마쳤으면 파트너 한 마디 자리를 **그리지 않는다**

### 3-3. MIS · 미션

#### `MIS-001` 미션 진행 · `/mission`
- [ ] 화면을 여는 것만으로 **세션이 생기지 않는다** (새로고침해도 세션이 안 늘어난다)
- [ ] 보기가 4개다
- [ ] 보기를 고르면 대화에 **번호가 아니라 문장**이 남는다
- [ ] 힌트를 여러 번 누르면 **같은 말이 되풀이되지 않는다** (`message.is_hint` 이력)
- [ ] Drill-down 은 **학생 응답 5회**까지다. 새 문제를 시작하면 0 부터 (COM-001 §7)
- [ ] 문제를 마치면 정답과 해설이 나온다
- [ ] AI 가 깨지면 학생 잘못처럼 말하지 않는다
- [ ] 모드 A·B 가 번갈아 돈다 (한 세션에서 둘 다 지나간다)

사진 문제(`MIS-002` · `MIS-003`)는 이 Route 안의 State 다.
- [ ] 사진을 올리면 비공개 버킷의 `<student_id>/` 아래에만 들어간다 (COM-007 §3-1)
- [ ] 인식 실패는 `verification_failed` 이고 정답률에 안 들어간다

### 3-4. PAR · 보호자

#### `PAR-002` 부모 HOME · `/parent`
- [ ] 부모 어휘다 — 「학습」 · 「추가 학습 필요」
- [ ] 최근 7일을 센다
- [ ] 평가점수가 보이되 **고칠 수 없다** (COM-003 §9)
- [ ] 학생이 없으면 **학생 등록 버튼**이 뜬다 (막다른 곳이 아니다)
- [ ] 학생이 있어도 **학생 추가** 버튼이 있다

### 3-5. RPT · 리포트

#### `RPT-001` 주간 성장 리포트 · `/parent/reports`
- [ ] 데이터가 없으면 「데이터 부족」 State 다
- [ ] 빈 표를 그리거나 숫자를 지어내지 않는다

#### `RPT-002` 리포트 상세 · `/parent/reports/[reportId]`
- [ ] 부모 어휘다
- [ ] 남의 `reportId` 를 주소창에 넣으면 「없음」이다 (RLS)

### 3-6. MY · 마이/설정

#### `MY-001` 마이페이지 · `/parent/my`
- [ ] MY-002~010 으로 가는 길이 다 있다

#### `MY-002` 학생 관리 · `/parent/my/students`
- [ ] 학생 목록과 「학생 추가」가 있다

#### `MY-003` 학생 프로필 · `/parent/my/students/[studentId]`
- [ ] 파트너 · 아이 로그인 · 삭제 요청은 **바꿀 수 있다**

- [ ] 삭제 요청한 학생에게는 로그인을 만들어 주지 않는다

#### `MY-004` 학생 추가 · `/parent/my/students/new`

#### `MY-005` 부모 회원정보 · `/parent/my/profile`

#### `MY-006` 마케팅 수신설정 · `/parent/my/marketing`
- [ ] 3종을 **각각** 받는다. 한 번에 묶는 스위치가 없다 (COM-007 §9)

#### `MY-007` 알림 설정 · `/parent/my/notifications`
- [ ] **켤 수 있는 스위치를 그리지 않는다.** 무엇이 없는지 적혀 있다

- [ ] 로그아웃된다

#### `MY-009` 회원탈퇴 안내 · `/parent/my/account/withdraw`
- [ ] **누르기 전에** 무엇이 사라지고 무엇이 남는지 적혀 있다 (COM-007 §5-2)

#### `MY-010` 회원탈퇴 확인 · `/parent/my/account/withdraw/confirm`
- [ ] **여기서 실제로 지워지지 않는다.** 접수까지만이라고 화면에 적혀 있다
