## 1. 문서 계층

| 계층 | 성격 | 변경 조건 | 예 |
|---|---|---|---|
| `COM-xxx` | 정책 · 기준 | **PM 전원 합의** | COM-001 ~ COM-007 |
| `DEV-xxx` | 구현 상세 | PR 리뷰 | DEV-001, DEV-002 |
| `prompts/` | AI Prompt 원문 | AI 코어 PM + 리뷰 | `prompts/logic-auditor.md` |

`COM`은 "무엇을 만들 것인가", `DEV`는 "어디에 어떻게 둘 것인가"를 다룹니다.

## 4. 충돌 시 우선순위

```text
COM  >  DEV
같은 계층이면 도메인 소유 문서가 우선

흐름 · 상태          → COM-001
데이터 · 필드명       → COM-002
화면 ID · State      → COM-003
코딩 규칙            → COM-004
기술 스택 · 환경      → COM-005
개인정보 · 아동데이터  → COM-007
폴더 · Route · 명명   → DEV-001 / DEV-002
```

코드가 문서와 다르면 **코드를 고칩니다.** 문서가 틀렸다고 판단되면 코드를 먼저 고치지 말고 문서 변경을 제안합니다. (COM-005 §10)

## 5. 문서 변경 절차

```text
변경 필요 발견
→ 기존 문서로 해결 가능한지 확인
→ 불가능하면 팀에 변경 제안 (사유 + 영향범위)
→ 합의
→ 문서 수정 + Version 올림 + Changelog 기록
→ Migration / 코드 반영
```

- `COM` 문서 수정은 **PM 전원 합의**가 있어야 합니다.
- `DEV` 문서 수정은 해당 오너 PM이 PR로 처리하고 리뷰만 받습니다.
- 수정 시 상단 헤더의 `Version` · `Updated`를 반드시 갱신하고 하단 Changelog에 한 줄 남깁니다.

### Version 규칙

| 변경 | 올림 |
|---|---|
| 오타 · 표현 정리 | 올리지 않음 |
| 항목 추가, 설명 보강 | `1.0 → 1.1` |
| 결정 변경, 필드/화면 추가·삭제 | `1.0 → 2.0` |
