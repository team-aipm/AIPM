# Figma ↔ MD 비교 검수

> **검수일:** 2026-09-29  
> **Figma:** `메티_화면 작업 중~` · 전체 10개 페이지  
> **문서:** `CLAUDE.md`, COM-001/002/003/007, DEV-001/002, 핵심 학습 메커니즘

## 0. 저장소에 반영하지 않은 항목

이 문서는 **2026-09-29 시점의 Figma 검수 기록**이다. 그 뒤 저장소에서 다르게
정한 것이 넷 있다. 아래는 이 문서가 아니라 COM 문서를 따른다.

| 이 문서 | 저장소 | 왜 |
|---|---|---|
| 아이 이메일을 인증번호로 확인하고, 없으면 `{id}@member.meti.app` 발급 (P0-2) | **부모가 아이 이메일을 직접 입력한다** | 도메인과 메일 수신 설정이 없다. COM-007 §2-2 |
| 휴대폰 본인확인 필수 (P1-8 · Account) | **미확정.** COM-005 §13 과 함께 묶어 둔다 | 본인확인 수단 계약이 없다. 2026-09-22 에 가입 폼에서 휴대폰을 뺐다 |
| 네이버 버튼 완전 제거 (P1-9) | **버튼은 둔다.** 기능은 만들지 않는다 | 화면에서 자리를 미리 잡아 둔다 |
| Route 를 `/parent/me/**` 로 (P1-F3 등) | **`/parent/my/**` 를 쓴다** | 이미 배포돼 있고 뜻이 같다. 결제(BIL) Route 도 DEV-002 를 따른다 |

나머지는 모두 반영했다. 도장·코인·캐릭터 해금·지난 미션·주말·3탭·자녀 최대
3명은 COM-001 · COM-002 · COM-003 에 들어가 있다.

## 1. 결론

핵심 사용자 흐름과 정책은 최신 MD에 맞게 정리되었다. 계정 분리, 학생 이메일,
개인정보·삭제, 14일 무료체험, 도장·코인, 캐릭터 해금, 지난 미션, 보호자 학습
상세와 미션 0개 리포트가 일치한다.

2026-09-29 최종 대조에서 활성 예외 화면의 이전 문구 2종, 화면 배치·명명 3건,
Route 인벤토리 누락 2건이 추가로 확인되었다. 아래 `최종 대조 잔여 항목`을
수정하기 전까지는 화면 인벤토리를 개발 기준으로 확정하지 않는다.

## 2. P0 · 개발 전 반드시 수정

### P0-1. 부모 계정의 학생 프로필 전환 제거

> **처리 완료:** 2026-09-28 · 활성 화면과 IA에서 제거, 기존 시안은 Archive 보존

Figma에 다음 활성 화면이 남아 있다.

- 학생 `03 · Profile Selection`
- 상태 `02 · Profile Selection States`
- 보호자 설정 `자녀 화면으로 전환`
- 학생 내 정보 `프로필 전환`

최종 MD는 학생·보호자 별도 로그인과 로그아웃 후 역할 변경을 요구한다.

조치:

- 위 화면과 IA 항목을 Archive로 이동
- 보호자 자녀 카드는 보호자용 상세 현황으로만 이동
- 학생 세션에는 프로필 선택·전환 메뉴를 노출하지 않음

### P0-2. 학생 계정 생성 흐름 교체

> **처리 완료:** 2026-09-28 · 기존 이메일 인증과 메티 전용 이메일 발급 흐름 추가,
> 직접 이메일 수정 제거, 예외 상태 화면 보완

현재 Figma:

- `자녀 이름(닉네임)` 수집
- 기존 이메일 직접 입력만 제공
- 이메일 인증번호 화면 없음
- 메티 전용 이메일 발급 화면 없음
- 이메일을 보호자가 화면에서 직접 변경 가능

최종 MD:

- 학생 실명과 학년만 수집
- 기존 이메일은 인증번호로 확인
- 이메일이 없으면 `{id}@member.meti.app` 발급
- 이메일 변경은 보호자 재인증 + 고객지원 절차

조치:

- `닉네임` 문구 제거
- 이메일 방식 선택, 기존 이메일 인증, 메티 아이디 생성 화면 추가
- 10분 만료, 60초 재발송, 5회 실패 시 해당 인증번호만 무효화 상태 추가
- 직접 이메일 수정 UI 제거

반영 결과:

- 학생 정보는 실명과 학년만 수집
- 기존 이메일은 인증번호 확인 후 계정 생성
- 이메일이 없는 학생은 보호자가 아이디를 정하고
  `{id}@member.meti.app` 형태로 발급
- 인증번호 10분 만료, 재발송 60초 대기, 5회 실패 시 현재 인증번호만 무효화
- 중복 아이디 제안과 개인정보 추정 아이디 경고 상태 추가
- 완료 화면을 기존 이메일과 메티 이메일로 구분
- 로그인 이메일은 읽기 전용으로 표시하고 변경은 고객지원 문의로 연결

### P0-3. 개인정보와 삭제 문구 수정

> **처리 완료:** 2026-09-29 · 사진 즉시 삭제와 확정 데이터 저장 정책 반영,
> 학생·보호자 삭제 문구 및 보호자 전용 30일 복구 상태 화면 추가

현재 Figma 자녀 동의 상세에는 업로드 이미지 보관이 미정으로 적혀 있다. 회원탈퇴
화면은 `탈퇴하면 바로 삭제돼요`라고 안내한다.

최종 MD:

- 사진은 OCR 확인·실패·취소 후 즉시 삭제
- 학생·보호자 탈퇴 요청 즉시 로그인 차단
- 30일 복구 후 개인정보와 학습데이터 완전 삭제
- 법정 보관 결제기록만 분리

조치:

- 동의문에서 이미지 장기 보관 표현 제거
- 사진 임시 처리와 즉시 삭제 안내 추가
- 회원탈퇴·학생 삭제 화면에 30일 복구기간과 이후 삭제를 명시
- 삭제 완료/복구 가능/복구 만료 상태 추가

반영 결과:

- 원본 사진과 임시 파일은 OCR 확인·실패·취소 후 즉시 삭제
- 학생이 확인한 미션 텍스트·구조화 데이터·학습 결과만 저장
- 학생 계정 삭제 요청 즉시 로그인과 이용 차단
- 계정을 관리하는 보호자만 30일 내 복구 가능
- 보호자 화면에 삭제 예정일·남은 기간과 계정 복구 행동 제공
- 보호자 탈퇴 시 모든 연결 계정의 이용 중단, 30일 복구, 이후 완전 삭제 안내
- 법정 보관 결제기록은 운영·학습 데이터와 분리 보관

### P0-4. 무료체험 7일 → 14일

> **처리 완료:** 2026-09-29 · 학생별 첫 실제 미션 시작 기준의 14일 무료체험으로
> 보호자 홈, 구독 준비·완료·관리, 종료 알림과 IA를 통일

보호자 홈과 구독 시작 화면에 `7일 무료 체험`이 남아 있다. 학생의 첫 실제 미션
시작부터 14일로 모두 변경해야 한다.

반영 결과:

- 보호자 CTA는 체험 즉시 시작이 아니라 `무료체험 준비하기`로 변경
- 각 학생의 첫 실제 미션 시작 시 학생별 14일 무료체험 시작
- 시작 예시가 9월 27일이면 체험 종료는 10월 10일, 첫 결제는 10월 11일로 통일
- 종료 2일 전 알림은 체험 12일째로 변경
- 준비 중·준비 실패·준비 완료 상태 문구를 실제 시작 시점과 구분
- 결제 후 7일 이내 환불 기준은 무료체험 기간과 다른 정책이므로 유지

### P0-5. 보상 기준을 미션 수 → 평일 참여 도장으로 변경

> **처리 완료:** 2026-09-29 · 학생·보호자 홈, 보상 관리와 전달 확인을
> 평일 참여 도장 기준으로 통일

현재 Figma는 `미션 30개 중 23개`, `목표 미션 수`처럼 완료 미션 수를 보상
진척도로 사용한다.

최종 MD는 월~금 오늘의 기본 일일 미션 10개를 모두 완료했을 때 하루 1개 지급하는
도장을 사용한다. 중간 이탈 시 완료한 미션의 코인만 유지한다.

조치:

- 모든 보상 진척 문구와 계산을 도장 기준으로 변경
- 빠른 목표값에 5 추가: `5/10/20/30/50/100`
- 직접 입력 `1~365`, 100 초과 비차단 경고 추가
- `달성`과 `보상 전달 완료`를 분리
- 달성 즉시 다음 예약 목표를 시작

반영 결과:

- 학생·보호자 HOME의 주간 집계를 `이번 주 참여 도장`으로 변경
- `1~9/10` 진행 중 날짜는 도장 미획득 상태, `10/10`에서만 획득 상태로 표시
- 누적 보상 진행을 `도장 n개 중 n개`, `보상까지 도장 n개`로 통일
- 목표 선택값을 `5/10/20/30/50/100`으로 구성
- `평일 오늘 미션 10개 완료 시 도장 1개`와 직접 입력 `1~365` 안내 추가
- 중간 이탈 시 완료한 미션별 코인은 유지하고 도장은 지급하지 않는 정책 반영
- 예상 소요일 대신 `도장 n개 더 모으면 달성`으로 표시해 주말·공휴일 오차 제거
- 보상 전달 확인은 진행도 초기화가 아니라 전달 완료 기록으로 안내
- 다음 예약 목표는 달성 즉시 시작되고 도장이 계속 쌓이는 정책을 명시

### P0-6. 최대 자녀 수 상태 통일

> **처리 완료:** 2026-09-29 · 활성 자녀 계정 화면을 최대 3명 기준으로 통일하고
> `3/3` 제한 상태를 추가

Figma에는 `2/3` 화면과 함께 `최대 2명`, `2/2` 화면이 활성 섹션에 공존한다.
최대 3명으로 통일하고 2명 제한 화면은 Archive로 이동한다.

반영 결과:

- 기본 목록은 `2/3`, 빈 목록은 `0/3`으로 유지
- 세 번째 자녀가 등록된 `3/3` 화면 추가
- `3/3`에서는 자녀 추가 CTA를 Disabled 처리
- 제한 안내를 `자녀는 최대 3명까지 등록할 수 있어요`로 통일
- 기존 `2/2`, `최대 2명` 화면은 Archive의 이전 정책 섹션에 보존

## 3. P1 · 핵심 UX 수정

### P1-1. 추가 캐릭터를 코인 사용 방식으로 해금

> **정책 변경:** 2026-09-29 · 메티·헤티는 기본 제공하고 추가 캐릭터는 코인을
> 사용해 영구 해금
>
> **처리 완료:** 2026-09-29 · 가격, 잔액 부족, 해금 가능, 확인, 처리 중, 성공,
> 실패와 캐릭터 변경 상태를 Figma와 MD에 반영

확정 가격:

- 큐리 500코인
- 포키 800코인
- 토리 1,200코인
- 모노 2,000코인

조치:

- 온보딩 선택은 기본 캐릭터 메티·헤티로 제한
- 추가 캐릭터 목록과 해금은 학생 `내 정보`에서 제공
- 잔액 부족, 해금 가능, 사용 확인, 성공, 실패 상태 제공
- 사용할 코인과 해금 후 잔액을 확인한 뒤 영구 해금
- 중복 요청과 실패 시 코인 이중 차감 방지

반영 결과:

- 온보딩의 잠긴 캐릭터 선택 시안은 Archive로 이동
- 활성 온보딩에서는 메티·헤티만 선택 가능
- 학생 내 정보에 추가 캐릭터 가격과 잠금 상태 표시
- 큐리 예시를 500코인 사용, 620 → 120코인으로 통일
- 코인 부족 시 필요한 잔액과 `미션하러 가기` 제공
- 해금 전 사용 코인과 남을 코인을 확인
- 처리 중에는 중복 행동을 막고 코인이 한 번만 사용됨을 안내
- 실패 시 코인이 사용되지 않았음을 안내하고 재시도 제공
- 해금 후 즉시 함께하기 또는 나중에 변경 가능

### P1-2. 오늘 완료 후 지난 미션 자동 권유 제거

> **처리 완료:** 2026-09-29 · 자동 권유 화면을 Archive로 이동하고 완료 결과의
> Primary Action을 `홈으로`로 변경

`학습하기 · 02 오늘 완료 후 지난 미션 묻기`는 오늘 미션 완료 직후 지난 미션
이어하기 Bottom Sheet를 노출한다.

최종 정책은 오늘 완료 후 HOME으로 이동하고, 사용자가 홈 카드 아래 `지난 미션`을
눌러 자율 진입하는 방식이다. 해당 Bottom Sheet를 제거한다.

반영 결과:

- `오늘 미션 다 했어! 지난 미션을 이어서 할래?` Bottom Sheet를 활성 흐름에서 제거
- 이전 자동 권유 화면은 Archive의 학생 홈·미션 진입 섹션에 보존
- 오늘의 미션 10개 완료 결과 화면 CTA를 `홈으로`로 변경
- 지난 미션은 HOME의 `지난 미션` 링크를 눌렀을 때만 목록으로 진입
- 완료 직후 추가 학습을 요구하거나 압박하는 행동을 제공하지 않음

### P1-3. 지난 미션 목록과 주말 상태 추가

> **처리 완료:** 2026-09-29 · 지난 미션 목록과 주말 상태를 추가하고,
> 가장 최근 미션을 우선하는 정보 위계와 진행률·CTA를 확정

학생 페이지에 다음 화면과 상태를 추가했다.

- 최근 7일 지난 미션 목록
- 만료·빈 목록·오류 상태
- 주말 `오늘은 자유롭게 학습해요`
- 남은 미션 유무에 따른 Primary Action

반영 결과:

- 가장 최근 미완료 미션을 `먼저 이어갈 미션` 강조 카드로 제공

### MD-2. 학생 답변 사진

상태 페이지에는 문제 촬영과 별개로 학생이 풀이 사진을 대화에 첨부하는 화면이

지원할지, 지원한다면 언제 삭제하고 어떤 텍스트만 남길지 별도 정책이 필요하다.

MVP에서는 풀이 사진 첨부를 제거하고 텍스트·추천 답변·대화만 제공하는 것으로
확정했다. 문제 촬영만 임시 OCR 입력으로 유지하며 COM-001·003·007과 CLAUDE.md에
반영했다.

> **Figma 처리 완료:** 2026-09-29 · 상태 페이지의 풀이 사진 첨부·업로드 중·업로드

### MD-3. 마케팅 동의 및 수신 설정

각 채널을 언제든 변경할 수 있다.

카카오 마케팅은 출시 시점에 미리 동의받지 않는다. 실제 발송 기능을 도입할 때
별도 동의 항목과 설정을 추가한다. 학생에게는 마케팅 동의를 받거나 발송하지 않는다.
