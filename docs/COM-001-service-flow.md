## 1. 핵심 원칙

-   회원(Account)은 학부모이다.
-   학생(Student)은 실제 학습자이며 부모 Account에 연결된다.
-   회원 1명당 등록 가능한 학생 수는 제한하지 않는다.
-   학생별 학습기록, Persona, 난이도, Logic Gap, Student Memory,
    무료체험, 구독 상태는 독립적으로 관리한다.
-   MVP 학습 과목은 수학이다.
-   첫 사용자는 MODE를 선택하지 않는다. AI가 먼저 문제를 내면서 서비스
    사용법을 경험하게 한다.
-   MODE A/B는 사용자에게 기술 용어로 노출하지 않는다.
-   AI가 정답을 확실히 검증할 수 없는 문제는 학습에 사용하지 않는다.
-   교육용 의도오답과 실제 AI 오류는 반드시 구분한다.

## 2. Master User Flow

``` text
서비스 접속
→ 부모 회원가입 / 로그인
→ 첫 학생 등록 (아이가 쓸 아이디·비밀번호까지 부모가 정한다)
→ 아이가 자기 아이디로 로그인
→ 홈
→ Persona 선택
→ 최초 사용: AI가 첫 문제 출제
→ 학생 답변
→ Adaptive Drill-down
→ 문제 완료 또는 추가 학습 필요
→ "이번엔 네가 문제를 내볼래?" 제안
→ 직접 입력 / 사진 촬영 / AI 다음 문제
→ 하루 기본 목표 10문제
→ 중간 종료 가능
→ 오늘의 학습 결과
→ 일일 학습기록 누적
→ 주간 학부모 리포트
→ 학생별 14일 무료체험 종료
→ 학생별 구독 안내
→ 부모 Account에서 결제
```

## 3. 회원가입 및 학생 등록

1.  신규 **부모**가 회원가입을 완료한다.
2.  첫 학생 등록 화면으로 이동한다.
3.  학생의 이름, 닉네임, 생년월일, 학년 등 필수 정보를 입력한다.
4.  닉네임 기본값은 학생 이름이다.
5.  **아이가 쓸 아이디와 비밀번호를 부모가 함께 정한다.** 필수다
    (COM-002 §4-1 · 2026-09-17 개정). 이것이 없으면 아이가 들어올 길이 없다.
6.  등록을 마치면 부모는 부모 HOME으로 돌아간다.
7.  아이가 그 아이디로 로그인해 자기 홈으로 들어간다.
8.  **아이가** Friend 또는 Villain Persona를 선택한다. 등록 시점의 기본값은
    `friend`이고, 아이가 바꾼다 — 함께 공부할 상대를 부모가 대신 고르지 않는다.
9.  추가 학생은 제한 없이 등록할 수 있다. 추가는 `MY-004`에서 한다.
10. 각 학생은 고유 `student_id`를 가진다.

## 4. Persona

-   `friend`: 격려하고 함께 해결하는 말투.
-   `villain`: 퀴즈 경쟁·도전 중심의 말투.
-   Persona는 학생별로 저장한다.
-   아이가 학생 HOME의 `Persona 변경`에서 바꾼다(COM-003 §4.2).
-   진행 중인 문제의 Persona는 바꾸지 않는다.
-   변경된 Persona는 다음 문제 또는 다음 학습부터 적용한다.
-   Persona는 말투와 몰입 경험에만 영향을 준다.
-   정답, 평가, 난이도, Answer Verification 로직에는 영향을 주지 않는다.

## 5. 최초 학습 온보딩

-   최초 학습에서는 학습방식 선택 화면을 먼저 보여주지 않는다.
-   학생 학년의 중간 난이도 문제를 AI가 먼저 출제한다.
-   학생이 답변하면 Adaptive Drill-down을 진행한다.
-   첫 문제 완료 후 AI가 자연스럽게 다음 행동을 제안한다.

예시 의도: - Friend: "이번엔 네가 나한테 문제를 내볼래?" - Villain:
경쟁형 Persona 문구로 동일 행동 제안.

선택: - 학생이 문제 내기 - 직접 입력 - 사진 촬영 - AI가 다음 문제 내기

## 6. 학습 모드

### 6.1 AI가 문제를 내는 흐름

``` text
Student Memory 조회
→ 문제 선정
→ AI 문제 출제
→ 학생 답변
→ 답변 평가
→ Adaptive Drill-down
→ 완료 상태 결정
→ 평가 저장
→ Student Memory 업데이트
```

### 6.2 학생이 문제를 내는 흐름

#### 텍스트 입력

``` text
학생 문제 입력
→ 문제 분석
→ 정답 검증
→ Answer Lock
→ AI 교육용 의도오답 생성
→ 학생이 AI 오류를 발견/설명
→ Adaptive Drill-down
→ 평가
```

#### 사진 입력

``` text
사진 촬영
→ 문제 인식
→ "내가 읽은 문제가 이게 맞아?" 확인
→ 학생 확인 또는 수정
→ 문제 분석
→ 정답 검증
→ Answer Lock
→ AI 교육용 의도오답 생성
→ Adaptive Drill-down
```

-   사진 문제는 학생 확인 전 학습을 시작하지 않는다.
-   정답 검증이 불확실하면 Answer Lock을 만들지 않는다.
-   검증 실패 시 재촬영, 수정 또는 다른 문제 선택을 안내한다.

#### 6.3 학생에게 모드를 고르게 하지 않는다 · **2026-09-30**

전에는 흐름이 둘이라 아이에게 어느 쪽으로 갈지 물을 여지가 있었다.
**묻지 않는다.**

```text
AI 가 낸 문제        아이가 푼다
아이가 가져온 문제    AI 가 틀리게 풀고, 아이가 그 틀린 곳을 찾는다
```

- 「내가 풀어볼래 / AI한테 내볼래」 같은 **선택 화면을 만들지 않는다.**
  문제를 가져오는 행위 자체가 이미 「AI 를 가르치겠다」는 뜻이다.
- **「이 문제의 답을 알고 있어?」를 따로 묻지 않는다.** 정답 검증이 끝나면
  곧바로 AI 의 오답 풀이로 들어간다. 한 번 더 묻는 화면은 없앴다.
- 아이가 대화 중 **「잘 모르겠어」**를 고르면 그때 함께 풀기 · 힌트로
  넘어간다. **같은 문제 안에서** 바뀐다 — 새 문제를 만들지 않는다.

#### 6.4 사진은 남기지 않는다 · **2026-09-30**

- 사진은 **입력 수단이지 학습기록이 아니다.**
- 아이가 확인 · 실패 · 취소한 **직후 원본과 임시 파일을 지운다.**
  아이가 확인한 텍스트와 구조화 데이터만 남는다 (COM-002 §23).
- 사진을 고르는 그 화면에서 **지운다는 것을 미리 알려준다.**
- 도형 · 그래프를 제대로 구조화하지 못하면 **학습을 시작하지 않고**
  다시 찍거나 글로 쓰라고 안내한다.
- **학습 대화 중에는 사진을 받지 않는다**(MVP). 아이가 풀이를 사진으로
  올리는 길은 만들지 않는다. 미션을 가져올 때의 촬영만 남는다.

## 7. Adaptive Drill-down

목표 사고 단계:

1.  판단
2.  근거
3.  규칙
4.  전이
5.  성찰

규칙: - 5단계를 무조건 모두 질문하지 않는다. - 학생 답변에서 이미 확인된
단계는 건너뛴다. - 부족한 사고 단계만 질문한다. - 한 문제에서 허용되는
**학생 응답**은 최대 5회이다. Drill-down 질문 횟수가 아니라 학생이 답하는
횟수를 센다. - **5회는 한 문제 기준이다. 새 문제를 시작하면 0부터 다시
센다.** - 충분한 이해가 확인되면 조기 종료할 수 있다. - 학생이
힌트를 사용했다고 실패로 표현하지 않는다. - 응답 횟수를 모두 쓰고
종료할 때는 §8의 종료 안내를 따른다.

### 관찰 영역과 `not_observed` (2026-09-30)

```text
최초 판단 · 이유 설명 · 규칙 이해 · 스스로 수정 · 다른 상황으로 전이
· 성찰 · 실제 도움 수준
```

- **본 것만 점수를 매긴다.** 관찰한 영역만 0~3 으로 적고, 대화에서 드러나지
  않은 영역은 `not_observed` 로 남긴다.
- 안 본 것을 0 으로 적으면 **못한 것처럼** 쌓인다. 0 과 「모른다」는 다르다.
- 조기 종료했다고 나머지를 0 으로 채우지 않는다. 조기 종료는 잘한 것이다.

## 8. 문제 완료 상태

### `completed`

-   핵심 개념 이해가 확인됨.
-   필요한 사고과정이 확인됨.
-   전이 수준까지 충분하다고 판단됨.

### `needs_review`

-   최대 Drill-down 후에도 핵심 이해가 부족함.
-   학생 화면에는 "실패"로 표시하지 않는다.
-   Logic Gap, Support Level, 취약 개념을 저장한다.
-   같은 개념의 더 쉬운 문제 또는 다른 표현의 문제를 출제한다.
-   보완 문제 성공 시 기존 난이도로 복귀한다.

### 종료 안내

문제를 종료할 때는 **정답과 해설을 먼저 보여준 뒤** 다음으로 넘어간다.
`completed`·`needs_review` 모두에 적용한다.

-   정답은 검증된 값(`verified_answer`)만 쓴다. AI가 그 자리에서 새로
    만들지 않는다. (§19)
-   해설은 정답 값을 그대로 옮기는 것이 아니라, **이 학생이 어디서
    갈렸는지에 맞춰** 쓴다.
    -   예: 128 ÷ 8 = 16 까지 갔으나 거기서 멈춘 학생에게는
        "16이 '어떤 수'야. 원래는 그걸 8로 나누려던 거였지."
-   문제 진행 중에는 정답을 알려주지 않는다. 종료 시점에만 보여준다.
-   "틀렸다"가 아니라 "여기까지 왔고 다음은 이거야"로 표현한다.

**왜 바꿨나.** 이전 규칙은 정답을 알려주지 않고 더 쉬운 문제로 다시
만나게 하는 것이었다. 실제 대화를 보면 학생이 응답 횟수를 다 쓴 뒤
자기 답이 맞았는지조차 모른 채 다음 문제로 넘어갔다. 그 상태로 받는
보완 문제는 앞 문제를 미해결로 남긴 채 쌓인다.
-   반복 실패 시 취약 개념으로 Student Memory에 누적한다.

### `system_interrupted`

-   AI/API/네트워크 등 시스템 사유로 정상 학습이 완료되지 못함.
-   정답률, Logic Gap, Support Level, 완료 문제 수에 반영하지 않는다.

## 9. 난이도 및 문제 선정

### 첫날

-   학생 `grade`를 기준으로 중간 난이도에서 시작한다.
-   해당 학년의 여러 수학 개념을 섞어 10문제를 구성한다.
-   별도의 "진단시험"으로 표현하지 않는다.
-   학습 과정에서 Initial Accuracy, Reasoning, Rule, Self-Correction,
    Transfer, Support Level, Logic Gap을 수집한다.
-   첫날 결과로 초기 Student Memory를 만든다.

### 2일차 이후

다음 요소를 조합한다. - 취약 개념 - 현재 수준 - 복습 필요 개념

기본 참고 비율: - 취약 개념 4 - 현재 수준 4 - 복습 필요 2

단, 비율은 학생 상태에 따라 조정 가능하다.

난이도 조절은 한 문제의 정오만으로 결정하지 않는다. 다음 데이터를
누적하여 판단한다. - Initial Accuracy - Reasoning Score - Rule Score -
Self-Correction - Transfer Score - Support Level - 반복 Logic Gap

### 학년을 넘나든다 (2026-09-28)

**제 학년 안에만 머물지 않는다.** 4학년 아이가 4학년에서 계속 막히면
3학년으로 내려가고, 거기서도 막히면 더 내려간다. 결손이 있는 아이에게
제 학년 문제만 주면 아무것도 되지 않기 때문이다.

```text
중1     1 2 3 4 5     ← 천장
6학년   1 2 3 4 5
5학년   1 2 3 4 5     ← 5학년 아이는 여기 3 에서 시작한다
4학년   1 2 3 4 5
3학년   1 2 3 4 5
2학년   1 2 3 4 5
1학년   1 2 3 4 5     ← 바닥. 레벨 1 은 `1 + 1` 수준이다
```

- **레벨 1 에서 더 내려가야 하면** `learning_grade − 1`, 레벨 5 로
- **레벨 5 에서 더 올라가야 하면** `learning_grade + 1`, 레벨 1 로
- 바닥(1학년 레벨 1)과 천장(중1 레벨 5)에서는 움직이지 않는다

천장을 중1 로 둔 이유는 **6학년 레벨 5 를 뚫는 아이가 실제로 나오는지
아직 모르기 때문**이다. 나오면 그때 다시 본다. 6학년 아이가 중1 을 푸는
것이 교육적으로 맞는지는 별도 판단이며, 여기서는 「막지 않는다」 까지만
한다.

**대상은 그대로 초등 4\~6학년이다.** 가입 학년은 바뀌지 않는다.

**학생에게 학습 학년을 보이지 않는다.** 5학년 아이가 「너는 4학년 문제를
푸는 중」 이라고 알게 되면 안 된다. 부모 화면에도 넣지 않는다.

### 두 개의 수준 값

같은 "난이도"를 담는 값이 둘이고, 성격이 다르다.

| 값 | 어디에 | 언제 바뀌나 | 무엇인가 |
|---|---|---|---|
| `learning_grade` | Student (COM-002 §4) | 레벨이 끝에서 더 움직일 때 | 지금 푸는 학년 |
| `current_difficulty` | Student (COM-002 §4) | 문제를 마칠 때마다 | 그 학년 안에서의 수준 |
| `current_level` | StudentMemory (COM-002 §10) | 하루를 마칠 때 한 번 | 이 아이가 요즘 어디쯤인가 |

문제마다 흔들리는 값과 "요즘 수준"은 다른 질문에 답한다. 둘을 하나로
합치면 다음 문제를 고르는 데 쓸 수 없거나, 리포트에 쓸 수 없게 된다.

**둘 다 서버가 정한다.** AI 가 문제마다 내놓는 난이도 의견
(`next_learning.difficulty`)은 참고하지 않는다. 같은 기록이면 언제나 같은
결과여야 이상할 때 재현해 볼 수 있다 — §10 Support Level 최종값을 서버가
계산하는 것과 같은 이유다.

### 판정 시점

`current_difficulty` 는 문제를 마칠 때마다 판정한다. 최근 3문제를 본다.

**단, 현재 수준에서 푼 문제의 평가만 본다.** 수준을 옮기면 그 전 평가는
다른 수준에서 푼 것이므로 다음 판정에서 제외한다.

이 조건이 없으면 같은 기록으로 연달아 움직인다. 하루 10문제에 판단 창이
3문제라, 하루에도 레벨이 여러 번 바뀌어 **아이의 수준이 아니라 그날의
운**을 따라간다.

`current_level` 은 하루를 마칠 때 **그날 낸 문제들의 난이도 중앙값**으로
정한다. 마지막 값(종가)을 쓰지 않는 것은 그날 마지막 한 문제의 운에
좌우되기 때문이다.

## 10. 힌트

-   학생이 힌트 버튼을 눌러 요청할 수 있다.
-   AI가 학생이 막혔다고 판단할 때 도움을 제안할 수 있다.
-   도움은 단계적으로 제공한다.
    1.  생각 유도 질문
    2.  약한 힌트
    3.  강한 힌트
-   힌트 사용은 학생 화면에서 감점으로 표현하지 않는다.
-   실제 사용한 도움 정도는 Support Level에 저장한다.

Support Level 0\~4:

  0. 도움 없이 스스로 해결
  1. 생각할 방향만 제시
  2. 관련 개념 또는 규칙 일부 제시
  3. 다음 행동을 할 수 있는 구체적 방향
  4. 정답 직전 수준의 강한 도움

-   턴별 Support Level은 오르내릴 수 있다. (`Message.support_level`)
-   한 문제의 최종 Support Level은 그 문제에서 나온 값의 **최대값**이며
    서버가 계산한다. (`Evaluation.support_level`)
-   힌트의 세기(Support Level)와 요청 횟수(`hint_count`)는 다른 값이다.

## 11. 하루 학습 세션

-   기본 목표는 10문제이다.
-   10문제는 강제 완료 조건이 아니다.
-   학생은 언제든 중간 종료할 수 있다.
-   `needs_review`도 학습한 1문제로 카운트한다.
-   `system_interrupted`는 완료 문제 수에 포함하지 않는다.
-   실제 완료 문제 수를 저장한다.
-   10문제 완료 시 오늘의 학습 결과 화면으로 이동한다.
-   **미션을 고르기 전 대화는 6턴까지다** (2026-09-30 추가). 닿으면
    나무라지 않고 「AI가 문제 내기 / 내가 문제 가져오기」 둘만 내민다.

문제 풀이에는 5턴 제한이 있는데(§7) **시작 대화에는 없었다.** 아이가
미션을 안 고르고 계속 떠들 수 있고, 한 마디마다 AI 호출이 한 번 나간다.
여섯으로 둔 것은 인사 · 근황 한두 마디 · 고르기까지면 넉넉하기 때문이다.
값은 `lib/ai/policy.ts` 의 `hostTurnLimit` 한 곳에 있다.

### 11-1. 평일과 주말 · **2026-09-30**

```text
월~금   오늘의 미션 10개를 새로 낸다
토·일   새 미션을 내지 않는다. 지난 미션과 가져온 미션만 자유롭게
```

- 주말에는 홈이 「오늘은 자유롭게 학습해요」로 바뀐다.
- **주말 학습도 리포트 분석에는 들어간다.** 도장 현황만 월~금으로 센다.
- 날짜가 바뀌면 새 10개가 시작된다.

### 11-2. 지난 미션 · **2026-09-30**

못 끝낸 오늘의 미션은 **7일 동안** 이어서 할 수 있다.

- 홈의 「지난 미션」을 아이가 **직접 눌렀을 때만** 들어간다.
- **오늘 다 끝낸 아이에게 지난 미션을 먼저 권하지 않는다.** 끝낸 직후에
  더 하라고 하는 것은 보상이 아니라 압박이다. 완료 화면은 홈으로 간다.
- 지난 미션은 **오늘의 도장과 코인에 넣지 않는다**(§11-A). 화면에도 그렇게
  적는다.
- 7일이 지나면 만료다. 만료를 실패처럼 표현하지 않는다.

## 11-A. 도장 · 코인 · 캐릭터 (2026-09-30 추가)

> 데이터 구조는 COM-002 §22. 화면은 COM-003.

두 가지를 나눠서 준다.

```text
도장   평일 오늘의 미션 10개를 다 했을 때  하루 1개
코인   미션 1개를 끝낼 때마다 10개 (하루 최대 100)
```

### 도장

- 월~금의 기본 10개가 **모두** `completed` 또는 `needs_review` 가 된
  순간에만 하루 1개.
- 1~9개에서는 주지 않는다. 지난 미션과 주말 학습으로는 못 채운다.
- 도장은 **부모와 약속한 보상**으로 이어진다. 목표 도장 수는 부모가 정한다.
- 달성해도 도장을 0 으로 되돌리지 않는다. 다음 목표가 곧바로 이어진다.
- 연속기록은 **곁들이는 정보**다. 토 · 일은 건너뛰고, 끊겨도 실패라고
  말하지 않는다.

### 코인

- `completed` · `needs_review` 인 **기본 미션 1개당 10개.** 하루 최대 100.
- `system_interrupted` · `verification_failed` · `abandoned` 에는 주지
  않는다. 다만 **정답률에도 반영하지 않는다**(§19).
- **완료 보너스는 없다.** 10개를 다 하면 도장 1개와 코인 100개다.
- 중간에 그만둬도 **한 만큼의 코인은 남는다.** 도장만 안 나온다.

### 캐릭터

```text
메티 · 헤티   기본 제공
큐리 500 · 포키 800 · 토리 1,200 · 모노 2,000  코인으로 영구 해금
```

- 해금은 학생 「내 정보」에서 한다. 온보딩에서는 메티 · 헤티만 고른다.
- **캐릭터는 말투와 연출만 담당한다.** 정답 · 평가 · 난이도 · 검증을
  바꾸지 않는다(§19).
- 코인이 모자라면 부족한 만큼을 알려주고 미션으로 보낸다. 결제로 보내지
  않는다.

## 12. 자동 저장 및 재개

-   대화 턴 단위로 자동 저장한다.
-   최소 저장 정보:
    -   `student_id`
    -   `session_id`
    -   `problem_id`
    -   현재 Drill-down 단계
    -   학생 답변
    -   AI 답변
    -   힌트/Support 상태
    -   현재 문제 상태
-   앱/브라우저 종료 또는 연결 끊김 후 마지막 저장점에서 복원 가능해야
    한다.

문제 도중 중단: - `이어서 하기` - `새 문제 시작하기`

전날 10문제 미완료: - `어제 학습 이어하기` - `오늘 새로 시작하기`

새로 시작해도 기존 학습기록과 Student Memory는 삭제하지 않는다.

## 13. 학생용 오늘의 학습 결과

상세 평가점수는 학생에게 직접 노출하지 않는다.

표시 예시: - 오늘 도전한 문제 수 - 스스로 고친 문제 수 - AI 도움 없이
해결한 문제 수 - 오늘 잘한 점 - 다음에 연습할 점

내부적으로는 상세 평가값을 계속 저장한다.

## 14. 학부모 리포트

-   매일 학습 결과를 누적한다.
-   주 1회 상세 주간 리포트를 생성한다.
-   단순 정답률보다 사고과정 변화 중심으로 구성한다.

주요 지표: - Initial Accuracy 변화 - Self-Correction Rate - Support
Level 변화 - Transfer 변화 - 반복 Logic Gap - 취약 개념 - 다음 학습 방향

## 15. 무료체험

-   무료체험 기간: 14일
-   기준: `Student`
-   시작: 해당 학생의 최초 학습 시작 시점
-   학생별 최초 1회
-   여러 학생이 등록되어 있으면 각 학생이 독립적으로 14일을 가진다.
-   체험 중 핵심 학습 기능 전체 이용 가능
-   체험 중 학습기록, Logic Gap, Student Memory, 리포트 정상 저장

## 16. 구독 및 결제

-   구독 단위: 학생 1명당 1구독
-   결제 주체: 부모 Account
-   부모가 원하는 학생만 구독할 수 있다.
-   학생마다 구독 상태를 독립적으로 관리한다.
-   결제수단과 결제내역은 부모 Account에서 관리한다.

상태: - `trial` - `active` - `payment_failed` - `expired` -
`cancelled` - `reactivated`

### 결제 실패

-   결제 실패 후 3일 유예.
-   유예기간에는 전체 학습 가능.
-   3일 안에 결제 성공 → `active`
-   유예 종료까지 실패 → `expired`

### 구독 종료

-   신규 학습 불가.
-   기존 학습기록 조회 가능.
-   기존 리포트 조회 가능.
-   Student Memory 유지.
-   재구독 시 기존 기록을 이어서 사용.

## 17. AI 오류 및 검증 실패

### AI/API 일시 오류

1.  자동 재시도
2.  성공하면 정상 진행
3.  재시도 실패 시 현재 턴까지 저장
4.  학생에게 간단한 재시도 안내
5.  `다시 해보기` / `나중에 하기`

### 문제/정답 검증 실패

-   추측하여 진행하지 않는다.
-   학습 시작을 차단한다.
-   재촬영, 문제 수정 또는 다른 문제를 안내한다.

### 평가

-   시스템 오류 문제는 학생 평가에서 제외한다.
-   교육용 의도오답과 시스템 오류를 동일한 상태로 저장하지 않는다.

## 19. 구현 금지사항

-   AI가 정답을 확신하지 못하는데 임의로 정답을 만들어 학습을 진행하지
    않는다.
-   학생의 시스템 오류를 오답으로 평가하지 않는다.
-   Persona가 정답/평가 로직을 바꾸지 않는다.
-   Student Memory를 세션 종료 시 초기화하지 않는다.
-   새 학습 시작 시 과거 학습기록을 삭제하지 않는다.
-   학생별 구독을 Account 전체 구독으로 임의 변경하지 않는다.
-   무료체험 시작일을 회원가입일로 임의 변경하지 않는다.

### 2026-09-30 에 더한 것

-   학생에게 학습 모드를 고르게 하지 않는다 (§6.3).
-   사진 원본을 학습기록으로 저장하지 않는다. 확인 · 실패 · 취소 뒤 즉시
    지운다 (§6.4).
-   학습 대화에서 풀이 사진을 받지 않는다 (MVP).
-   관찰하지 못한 평가 영역을 0 으로 적지 않는다. `not_observed` 다 (§7).
-   지난 미션과 주말 학습을 오늘의 도장 · 코인에 넣지 않는다 (§11-2).
-   도장을 평일 10개 완료가 아닌 기준으로 주지 않는다 (§11-A).
-   코인을 미션당 10개 · 하루 100개 밖으로 주지 않는다. 완료 보너스 없음.
-   오늘 미션을 끝낸 학생에게 지난 미션을 먼저 권하지 않는다.
-   연속기록이 끊긴 것을 실패 · 처벌처럼 표현하지 않는다.
-   보상을 달성했다고 모은 도장을 0 으로 되돌리지 않는다.
